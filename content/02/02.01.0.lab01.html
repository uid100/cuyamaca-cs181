C++ Input: cin vs. getline()

In C++, both cin and getline() are used to get input from the keyboard, but they work differently.

  • cin reads input only until it encounters a whitespace character (such as a space, tab, or Enter key). It is commonly used for single words or numeric values.
  • getline() reads an entire line of text, including spaces, until the user presses Enter. It is commonly used for sentences or full names.

Example:

Input: John Smith

cin >> name;          // Stores: "John"
getline(cin, name);   // Stores: "John Smith"

Use cin when reading individual values such as numbers or single words, and use getline() when you need to capture an entire line of text that may contain spaces.

Coding style and conventions

Although these may not prevent your code from compiling and running, following good coding style and conventions will help make your code more readable, maintainable, and professional.

Variable Naming

Identifier names such as constants, variables, methods, classes, and even filenames should be descriptive and meaningful.

Avoid single-letter names unless they are commonly used for loop counters.

By convention, use lowerCamelCase for variable and method names, and UPPER_CASE for constants. In addition to ensure they are treated as immutable, it is recommended to use the const keyword when declaring constants.

In later chapters, you will see the use of PascalCase (UpperCamelCase) for class names.

Indentation

Use consistent indentation to make your code easier to read. Typically, 4 spaces are used for each level of indentation.

Indent code inside braces by 4 spaces

Indentation does not affect how a C++ program runs, but it makes the program easier for humans to read. Code inside a block (between { and }) should be indented consistently so the structure of the program is clear. Consistent formatting improves readability and helps others understand and maintain your code.

Formatting

Avoid writing code with source lines that are hundreds of characters long. As a general rule, keep lines within 80 characters whenever practical, and never exceed 100 characters. Code should fit comfortably on a printed page and be easy to read without horizontal scrolling. If a statement becomes too long, break it into multiple lines with meaningful indentation. Remember: code is read far more often than it is written.

Most common IDEs support automatic indentation, with consistent code conventions and formatting by default. Do not override these defaults until you are more experienced with the language and its conventions.

Consistent indentation helps in understanding the structure and flow of your code.
